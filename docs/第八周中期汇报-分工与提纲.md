## 三、三人分工（各 33%）

按"模块 Owner 制"拆分：每块有唯一负责人，避免三个人都改同一处；工作量按开发、测试、文档综合估算。

| | 成员 A（组长） | 成员 B | 成员 C |
|---|---|---|---|
| **主责** | 播放与集成 | 数据与队列 | 界面与歌词 |
| **代码模块** | `PlaybackService`、ExoPlayer、`MediaSession`、媒体通知、`MediaController` 连接、`PlayerViewModel` 命令转发 | MediaStore 扫描与权限、Room 三表（`tracks` / `playlists` / `playlist_items`）、`LibraryRepository`、队列 / 随机 / 循环逻辑 | 三个页面与 Material 3 主题、播放器与曲库交互、LRC 解析 / 同步 / 导入、`LyricsRepository` |
| **测试** | 播放状态机、通知与后台播放手工用例 | 13 项单元测试、扫描与入库校验 | 歌词解析用例、UI 走查 |
| **交付物** | 可演示 APK、CI 绿灯、最终集成 | 曲库与队列、测试报告 | UI 与歌词、截图 / 演示视频、报告模板 |
| **个人报告重点** | 播放架构与系统集成 | 曲库与数据管理 | 界面与歌词实现 |
| **工作量** | 33% | 33% | 33% |

**共同承担（不计入上述百分比，三人均摊）**

- 每人一份不少于 15 页的个人报告（整体框架可共用，重点写各自分工）。
- 联调测试、交叉 Code Review、答辩准备。
- 第八周现场角色：**A 主讲 PPT，B 现场演示，C 记录老师提问并整理待办**。

**为什么这样分是平的**

- A 的"集成 + CI"与 B 的"数据 + 单测"、C 的"UI + 歌词 + 素材"在工时上接近，且互不阻塞。
- 接口在 P4 已经定死（`playTrack()`、`scanLibrary()`、`importLyrics()` 等），三人可以并行开发。
- 每人都有"代码 + 测试 + 文档"三类产出，个人报告不会有人无内容可写。
