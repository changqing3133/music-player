# 03_结论：6/6 必选、1/1 可选已全部完成

先给结论：课程要求六项必选、一项可选，我们全部完成，另外补了三项系统级扩展。这个项目是本地优先的，扫描、播放、歌词全部在本机完成，不申请 INTERNET 权限，所以没有接口失效、隐私上传和演示断网的风险。支持 MP3、AMR、AAC、OGG、FLAC、WAV 六种格式。三条原则贯穿全项目：单一播放实例，ExoPlayer 只在 PlaybackService 里创建；单一状态出口，界面只观察 LiveData；单一视觉语言，用 Material 3 令牌统一三个人的页面。

---

# 04_三个人的代码，怎么合成一个应用？

架构分四层。最上面是界面：MainActivity 承载三个页面和底部导航，曲库页负责扫描和列表，播放页负责控制、歌词和进度。命令交给 PlayerViewModel，它通过 MediaController 这个 Binder 桥发命令，再把服务回传的状态汇聚成 LiveData。最下面是数据层：PlaybackService 持有唯一的 ExoPlayer 实例，LibraryRepository 管 Room 和 MediaStore，LyricsRepository 只管 LRC 文件。层与层之间只走 playTrack、seekTo、next、scanLibrary 这些明确接口，谁也不直接持有对方的引擎。

# 05_三个人各自负责什么？

三个人按模块 Owner 制拆分，各承担三分之一。A 是组长，负责播放服务、通知与后台、Controller 和 ViewModel，以及 Git、CI 和最终集成，交付可演示 APK 和 CI 绿灯。B 负责 MediaStore 扫描、Room 三张表、队列与随机循环，还有单元测试，交付曲库、队列和十三项测试。C 负责三个页面、播放器与曲库交互、LRC 解析和演示材料。除此之外，每人十五页个人报告、联调测试、答辩准备是共同承担的；本周由 A 主讲、B 演示、C 记录问题。

# 06_怎么保证三个人的环境一致？

环境一致不靠口头约定，靠文件。版本矩阵固定为 JDK 25、Gradle 9.6.0、Android Gradle Plugin 9.4.0、compileSdk 37、minSdk 24。三件事保证三个人一样：第一，Gradle Wrapper 锁版本，依赖集中在版本目录里声明；第二，main 和 develop 加功能分支，提交钩子校验 Conventional Commits，PR 必须过 CI 才能合入；第三，界面先改 Material 3 令牌再改页面，共用 item_track 布局。结果是 CI 上十三项单测全过、Lint 零错误、APK 十一兆，对应提交 c44060e。本地和 CI 跑的是同一条 gradlew 命令。

# 07_必选、可选、扩展，完成到什么程度？

完成度逐项过。必选六项全部可演示：多格式播放覆盖四种主格式，还兼容 FLAC 和 WAV；播放控制有播放暂停、快进快退十秒、拖动进度；歌曲信息显示标题、艺术家、专辑、时长和内嵌封面；扫描用 MediaStore，Room 自动入库；上一首下一首遵守三秒规则，超过三秒先回本曲开头；循环支持顺序、列表循环、单曲循环和队列级洗牌。可选做了 F4 同步歌词，LRC 时间轴解析、当前行高亮、自动滚动，支持应用内导入。扩展三项是后台播放与媒体通知、文件管理器打开方式、内嵌封面。构建和十三项单测已经通过，真机回归还没闭环，计划十一月七号前完成。

# 08_代码真的集成、真的可复现吗？

代码管理用 Git 加 GitHub。每次 push 触发 GitHub Actions，流水线五步：拉取仓库、装 JDK 25、装 Android SDK、跑单元测试、打 debug APK。最新一次运行十三项测试全过，Lint 零错误，APK 十一兆，提交 c44060e，运行编号二，日期十月十七号。仓库在 github 上的 changqing3133 斜杠 music-player，主分支加功能分支，PR 必须过 CI 才能合入。也就是说，任何人把代码拉下来，跑同一条命令，都能得到同一个 APK。

# 09_还剩哪些风险，谁来闭环？

风险三项，都有负责人和日期。第一项是范围：网易云私有目录不被 MediaStore 索引，点 ncm 是加密格式，我们只支持可播放音频，并在 README 里写明边界，B 在十月二十四号已经划定。第二项是歌词：只支持本地 LRC，因为不申请网络权限，所以提供应用内导入和同名文件查找，C 已完成。第三项是真机回归：当前没有连接设备，需要借设备或模拟器，覆盖播放、通知、蓝牙按键、歌词滚动和扫描，A 在十一月七号前完成。后面的里程碑排到十一月二十号提交截止。
